# Trains of thought: definitions

Generated by `gen-intheworks-v2.py`. Edit the script, not this file.

## The shared shape

```
Every primitive runs the same three steps. A primitive is
defined by what it changes, what its criterion is, and what
it emits. Nothing else varies between them.

1. ACT
   Do the operation, given directions and inputs.

2. ASSESS
   Test the result against this primitive's named criterion.
   The criterion is fixed per primitive and is never a
   general "is this good".

3. ROUTE
   Loop back to ACT with a sharpened input, or emit.
   Every loop must be bounded. A loop that cannot make its
   input strictly sharper emits with the failure recorded.

Format failure is separate from criterion failure. A
malformed result is retried mechanically and never reaches
ASSESS.
```

## Stream types

```
Streams are typed message streams. Each entry is
modifiable and retains its previous states. Every stream
cites the entry that created it.

ORIGIN STREAM
Opens with the first message of a conversation. Exactly one
per conversation.

MAJOR STREAM
A child of the origin stream, created by the first Split.
One per top-level thought.

TOT STREAM
Forms inside a major stream, created by any later Split.
Tight-scoped, one line of thought.

Note: as written, Major and TOT differ only by depth, not
by kind. See open question 1.
```

## Type dispatch

```
The type is assigned when the entry is written.
Dispatch is a lookup, not a judgment call.

  COMPOUND    carries more than one thought   -> Split
  QUESTION    asks for something not present  -> Recall
  INFO        asserts something               -> Substantiate
  OPEN SPLIT  has live children               -> Merge

An entry whose type cannot be assigned is a COMPOUND by
default and gets Split. Splitting an atom is cheap; running
Substantiate on a compound is not.
```

## The four primitives

| primitive | changes | criterion |
|---|---|---|
| SPLIT | topology: 1 stream -> n streams | COVERAGE AND DISJOINTNESS |
| RECALL | content: entry -> entry + retrieved | SPAN |
| SUBSTANTIATE | metadata: entry + retrieved -> + confidence | EVIDENTIAL SUFFICIENCY |
| MERGE | topology: n streams -> 1 entry | AGREEMENT |

### SPLIT

*topology: 1 stream -> n streams*

**ACT**

```
Source message in scratchpad. Carve it into distinct
thoughts, one per intended stream. Emit as a formatted
set, each piece citing the source entry.
```

**ASSESS**

```
COVERAGE AND DISJOINTNESS
Do the pieces together account for the whole source?
Does any piece overlap another?
```

**ROUTE**

```
Fails coverage: re-carve with the uncovered remainder
named as input.
Fails disjointness: re-carve with the overlap named.
Passes: the mechanical process creates the streams from
the final format.
```

**EMITS**

```
n typed streams, each citing the source entry.
```

### RECALL

*content: entry -> entry + retrieved*

**ACT**

```
Given the thing to recall about, plus directions on which
memory types to search, retrieve into a specified format.
```

**ASSESS**

```
SPAN
Is the recalled set the right width for what was asked?
Too wide means the ask was vague. Too narrow means it
was mis-scoped.
```

**ROUTE**

```
Fails: hand back to ACT with a clearer piece to recall
about, carrying the original recall along as new fields.
Bound: each loop the piece must be strictly narrower
than the last. If it cannot be narrowed, emit with the
span failure recorded.
```

**EMITS**

```
Retrieved content, plus the full recall trail.
```

### SUBSTANTIATE

*metadata: entry + retrieved -> + confidence*

**ACT**

```
Takes recalled info as an INPUT. It does not fetch it;
the caller runs Recall first.
Given the claim and the recalled info, use dispatchable
tools to falsify or substantiate the claim.
```

**ASSESS**

```
EVIDENTIAL SUFFICIENCY
Did the tools reach the claim at all? A tool that could
not address the claim is no evidence, not weak evidence.
```

**ROUTE**

```
Insufficient, another tool could reach it: loop to ACT
with that tool named.
Insufficient, no tool can reach it: emit as unreachable.
Sufficient: emit with a confidence measure.
```

**EMITS**

```
The claim, its confidence, and what was tried.
```

### MERGE

*topology: n streams -> 1 entry*

**ACT**

```
The inverse of Split, called automatically per split.
Collect the terminal entries of the child streams and
compose them against the source entry the split cited.
```

**ASSESS**

```
AGREEMENT
Do the children contradict each other, or contradict
each other's confidence?
```

**ROUTE**

```
Contradiction: Split a new TOT whose subject is the
contradiction. Do not resolve it here.
Agreement: write the composed result into the parent
stream as a new entry.
```

**EMITS**

```
One parent entry, citing every child.
```

## Open questions

```
1. Major vs TOT. As written the difference is depth alone, which makes one
   of the two names redundant. Either give Major a property TOT lacks, or
   collapse to one name plus a depth field.

2. Nothing commits. Recall fetches, Substantiate checks, Split divides,
   Merge composes. No primitive takes a position. If that is deliberate,
   say so, so the absence reads as a decision rather than a gap.

3. Merge on contradiction Splits a new TOT, which can itself Merge into a
   contradiction. That recursion needs a bound.

4. Retry budgets. Split, Recall and Substantiate each loop. Is the budget
   per-primitive, per-stream, or per-conversation?

5. Confidence is produced by Substantiate and consumed by Merge. Nothing
   says what scale it is on or how two of them compare.
```
