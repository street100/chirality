# AUDIT — the harness/auth arc, adversarially tested

**2026-08-22.** Run because "all phases green" has meant very little in this
session: seven of my premises were wrong, and one stashed lint check would have
reported `ok` forever while silently deleting a live check. Re-running suites
that already passed proves nothing. This audit asks the two questions that do:
**do the gates have teeth**, and **is any of it built-but-unadopted.**

## 1 · Teeth — source mutation, one gate at a time

Method: mutate the CHECK in the compiler SOURCE, rebuild, run only that gate,
restore. A gate that still passes with its check removed is decoration.

| gate | mutation | result |
|---|---|---|
| E76 chokepoint (H7) | `(ck-tiprog linux-syscalls image)` → `(sok)` | **3 of 12 FAIL** — exactly the poison cases |
| profile subset (H8) | `manifest-offender`'s `(some ps)` arm → `(none)` | **3 of 12 FAIL** — the three profile refusals |
| module coordinate (E160) | `kind-offender` → always `(none)` | **4 of 29 FAIL** |
| linear mint (E159) | `linear-binder-bad` → always `false` | **7 of 21 FAIL** |
| profile port-set (H6) | `ty-crosses` → always `true` | **1 of 31 FAIL** |
| `chirality check` (H5) | fed a known-bad file directly | discriminates: unknown-name → exit 1, clean → exit 0 |
| downstream roots (H7) | — | needed no mutation; it caught a REAL defect the day it was added (`compile-all` declaring no imports) |

**Every gate fails when its check is removed.** None is self-confirming.

### ⚑ A methodology finding worth keeping
My first attempt mutated the **B1 binary** and every gate still passed. Not a
teeth failure — the tests re-blob the CLEAN TREE and build a fresh compiler with
that binary, so a mutant compiler compiling clean sources **emits a clean
compiler**. The mutation washes out in one generation. Only a self-propagating
(trusting-trust) change survives that. This is worth knowing before anyone else
concludes "the gates are fake" from a binary mutation.

## 2 · Adoption — is it live, or shelfware?

This repo has FIVE recorded instances of built-but-unadopted (`checked-sys-lib`,
`string-utils` pre-E151b, E42, E147's obsolete workaround, `row-infer`). So:

- **E160 in a real build:** flipping `pretty.chiral`'s true `(pure)` to `(crosses)`
  makes an ordinary program importing it **refuse to emit**. Not test-only.
- **E160 on the compiler itself:** flipping `prelude`'s claim **refuses the
  compiler's own self-build**. 5 of the 6 annotations are in the compiler blob
  (`prelude`, `collections`, `string-utils`, `target-linux`, `ports`).
- **E76 on the compiler itself:** already proven — a poisoned registry refuses
  the compiler compiling its own source.

## 3 · End-to-end — the editor, actually used

```
  -> screen contained the typed text
  -> exited status 0
  -> /tmp/edit-target.chiral on disk, 20 bytes: (def answer I64 42)
  -> chirality check on the editor's own output: OK, exit 0
```
The editor writes chirality the compiler accepts. That loop had never been closed in
this session — every prior claim was "it compiles".

## 5 · What this audit did NOT establish

- **The Python oracle is unrunnable here** (no pytest), and the `kind` form now
  makes it raise `unknown toplevel form kind` on six modules. The advisory
  differential is dark. That is a real gap, not a clean bill.
- **Mutation coverage is per-gate, not exhaustive.** I mutated one check per
  gate. A second, unmutated check inside the same gate could still be dead.
- **E52** remains a standing UNRESOLVED flag (ledger vs INDEX), by design.
- **The closconv bound is pinned, not closed:** a `(pure)` claim still cannot see
  a crossing reached only through a lifted lambda. Two tests hold the line.
