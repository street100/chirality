Abstract
We present EverCrypt: a comprehensive collection
of veried, high-performance cryptographic functionalities avail-
able via a carefully designed API. The API provably supports
agility (choosing between multiple algorithms for the same
functionality) and multiplexing (choosing between multiple im-
plementations of the same algorithm). Through abstraction and
zero-cost generic programming, we show how agility can simplify
verication without sacricing performance, and we demonstrate
how C and assembly can be composed and veried against
shared specications. We substantiate the effectiveness of these
techniques with new veried implementations (including hashes,
Curve25519, and AES-GCM) whose performance matches or
exceeds the best unveried implementations. We validate the
API design with two high-performance veried case studies built
atop EverCrypt, resulting in line-rate performance for a secure
network protocol and a Merkle-tree library, used in a production
blockchain, that supports 2.7 million insertions/sec. Altogether,
EverCrypt consists of over 124K veried lines of specs, code,
and proofs, and it produces over 29K lines of C and 14K lines
of assembly code.

B. Threat Model
EverCrypt proves that all of its implementation code is
functionally correct, meaning that it matches a high-level
mathematical description of its intended effect. As intermediate
lemmas, it also proves memory and type safety. With respect
to security, EverCrypt relies on the techniques developed
by HACL

 82
common side channels. Specically, using the techniques
discussed in Section II-A , it proves that secrets never inuence
branches, memory accesses, or timing-dependent instructions
(e.g., division), hence preventing leaks based on timing or cache
behavior. This does not necessarily rule out more advanced
side channel attacks based, e.g., on electromagnetic radiation
or speculative execution.

than 10-20 seconds. We also exploit the parallelism of modular
verication to bring the latency of a full system verication
down to less than 18 minutes on a powerful desktop machine.
Altogether, designing, specifying, implementing, and veri-
fying EverCrypt took three person-years, plus approximately
one person year spent on infrastructure, testing, benchmarking,
and contributing bug xes and other improvements to F
?
.
IX. C
ONCLUSIONS
EverCrypt provides application developers with the func-
tionality, ease of use, and speed they expect from existing
cryptographic providers, while guaranteeing correctness and
security of the code. Its API is carefully designed to support
algorithm agility and multiplexing, but seals many details
behind an abstraction boundary to simplify verication for
clients. We program its implementation generically to reduce
specication bloat and increase code and proof reuse, without
harming performance. Indeed, our targeted implementations of
hashes, AEAD, and ECC all meet or exceed the performance
of state-of-the-art unveried implementations, and handily
exceed previous veried implementations. Our QUIC transport
security layer and our Merkle trees demonstrate the utility of
EverCrypt's API in verifying client applications and meeting
their demands for high performance.
