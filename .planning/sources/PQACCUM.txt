                                                            Abstract
            An accumulator is a cryptographic system for compactly representing a set of elements such that
        every element in the set has a short membership witness. A dynamic accumulator, furthermore, allows
        elements to be added to and deleted from the accumulator. Camenisch and Lysyanskaya (CRYPTO’02)
        constructed the first dynamic accumulator under the strong-RSA assumption and showed how it can
        be used to enable revocation of anonymous credentials. In this paper, we give a lattice-based dynamic
        accumulator tailor-made for enabling revocation of post-quantum anonymous credential systems. As a
        concrete example, we instantiate our dynamic accumulator on top of the anonymous credential system
        implemented in the LaZer library (ACM CCS 2024).


1       Introduction
A cryptographic accumulator [BdM93] allows one to represent a set S by a short digest AS . The important
feature of an accumulator is that it supports compact proofs of membership: corresponding to each element
x ∈ S, there is a short witness wx,AS attesting to the fact that x is in fact in the set represented by AS .1 .
The security properties of a cryptographic accumulator guarantee that (informally) an adversary cannot find
a value x ∈/ S and a membership witness wx,AS .
    Further, an accumulator is dynamic [CL02a] if elements can be added to or deleted from the set such that
membership witnesses can be quickly updated. In other words, if x ̸= y ∈ S and S ′ = S − {y}, then AS ′
can be efficiently computed from AS and y (rather than the entire S ′ ) and wx,AS ′ can be efficiently computed
from wx,AS , AS , AS ′ and a short (independent of the size of S) update message. A dynamic accumulator
with free addition [BCD+ 17], [KL24] allows an accumulator manager in possession of a trapdoor to add
elements to the set S without modifying the value AS : the trapdoor allows the manager to compute wx,AS
for any x. As a result, the value A of the accumulator would need to change only when an element is
deleted. The security properties of a dynamic accumulator guarantee that (informally) an adversary cannot
find a value x ∈/ S and a membership witness wx,AS even when S and AS are the result of a game between
the adversary and the challenger where the adversary directs the challenger to add and remove elements and
provide witnesses for added elements.
    1
    Sometimes this flavor of accumulator is called a positive accumulator to tell it apart from the negative accumulator that admits
witnesses of non-membership attesting to z ∈/ S; and from the universal accumulator where for any x there is a witness, either of
membership if x ∈ S or of non-membership if x ∈   / S [LLX07, BCD+ 17]. In this paper we don’t consider negative and universal
accumulators and thus do not discuss them further.

    A dynamic accumulator with free addition is a convenient way to handle revocation of credentials [BCD+ 17].
Together with a public key for verifying a credential, the credential issuing and revocation authority pub-
lishes an initial value for an accumulator A0 = A∅ for which it has a trapdoor; this value will be updated
when credentials are revoked. To issue a credential corresponding to x, the authority computes the witness
wx,At where At is the current value of the accumulator at step t; wx,At is then given to the credential holder;
the set S is updated to include x so that St+1 = St ∪ {x}, but the accumulator value does not change, i.e.
At+1 = At . To revoke a credential corresponding to y ∈ St , the authority updates the accumulator value
from At to At+1 that corresponds to the set S ′ = S − {y}; the dynamic nature of the accumulator allows
this operation to be done efficiently. The authority then publishes At+1 and the short update message that
allows each unrevoked credential holder to update its witness from wx,At to wx,At+1 .

Application to revocation of anonymous credentials. Recall [BBC+ 24] that in an attribute-based cre-
dential system, users obtain credentials from issuing organizations; on a high level, a credential is the orga-
nization’s signature on a vector of values (a1 , . . . , aℓ ) corresponding to ℓ attributes of the user’s identity, for
example, the user’s ID number, expiration date, age, and other application-specific information; these are
obtained in a privacy-preserving manner in which the issuer may not learn the values of all of the attributes,
but just the fact that they satisfy its credential-granting policy. When showing an anonymous credential to a
verifier with a particular access control policy, a user does not show its attributes and the issuer’s signature
in the clear, but instead carries out a zero-knowledge proof of knowledge of a credential that satisfies the
verifier’s policy.
    Camenisch and Lysyanskaya [CL02a] demonstrated that dynamic accumulators were a useful primitive
for constructing anonymous credential systems with revocation. Let one of the credential attributes be
associated with a revocation handle: the issuer samples a fresh handle x every time it issues a credential, and
sets the value of the user’s revocation attribute (say the ith attribute is the revocation attribute) to it: ai := x;
then it issues the credential with attributes (a1 , . . . , aℓ ) to the user, and also adds x to the accumulator set S
represented by AS and sends (x, wx,AS ) to the user.
    When showing an anonymous credential, a user Alice would not reveal its revocation handle x and the
witness wx,A in the clear. Instead, Alice would compute a (non-interactive) cryptographic commitment to
these values, and use a zero-knowledge proof system to prove that (1) she is in possession of the credential
with revocation attribute x; and (2) she is in possession of the witness w that x belongs to the set represented
by A . Thus, it is important that a cryptographic accumulator used for the purposes of anonymous credential
revocation support a commit-and-prove paradigm for elements of the accumulated sets and their witnesses.
    When a credential with revocation attribute y needs to be revoked, the credential issuer’s accumulator
AS is updated to AS ′ = AS−{y} . Alice whose revocation attribute x ̸= y is still in the accumulator can
update her witness wx,AS to wx,AS ′ and will still be able to show her credential. However, the security
properties of a dynamic accumulator ensure that Bob whose revocation attribute is y will no longer be able
to do so.

Post-quantum-secure cryptographic accumulators. State-of-the-art constructions of positive dynamic
accumulators are based on the strong RSA assumption [CL02a, LLX07, KL24] or the q-strong Diffie-
Hellman assumption [Ngu05, ATSM09, CKS09] that do not hold in the post-quantum setting. Their free-
addition counterparts allow to add elements without modifying the accumulator’s value [BCD+ 17, KL24,
KB21, JML24]. Another approach — Merkle-tree-based constructions [RY16] — only yields an accumu-
lator in the special case where the size of the universe is polynomial. Then the accumulator value AS is
the root of the Merkle tree where leaf i contains 1 iff i ∈ S. A lattice-based construction of Papamanthou
et al. [PSTY13] uses Ajtai’s Module-SIS-based hash function [Ajt96] to instantiate a Merkle tree, which
therefore yields a bounded-size accumulator. Building on this work, Yu et al. [YAY+ 18] adapted Papaman-

Our results. In this paper, we give the first post-quantum dynamic accumulator with free addition that
works in the commit-and-prove paradigm and is directly applicable to revocation of anonymous credentials
in existing lattice-based constructions [BLNS23b], [JRS23], [LCL+ 23] [AGJ+ 24]. Our first, simplest con-


                                                                  3
structions (based on the Agrawal, Boneh and Boyen signature scheme [ABB10]) comes with caveats: we
relax the definition of security so that it is still sufficient for the desired application in two ways: (1) we
require selective security, i.e. the value x∗ ∈ / S whose membership in the accumulator the adversary aims
to forge is given to the challenger in advance; and (2) the security game is replacement-free, i.e. once some
element y is removed from the accumulator it can never be added back in. (We note that the same caveats
apply to the security of the De Castro and Peikert accumulator for the case where only deletions and not
additions cause the accumulator value to change.) This is good enough for our application: To see why (1) is
a reasonable relaxation, recall that it is the credential issuer who chooses the revocation handles that it then
authenticates as part of the anonymous credential, so the adversary does not have the freedom to choose any
value for x∗ in order to use a revoked credential. As for (2), we may simply require that, once a credential is
revoked, it cannot be reinstated with the same revocation handle; the user must obtain a new credential with
a new revocation handle. For settings where (1) and (2) could be problematic, we give an upgraded version
of our construction: an adaptively secure positive dynamic accumulator obtained by combining our first
construction with an adaptively secure digital signature. As we explain in Section 5.3 (see Table 2), when
we set the security parameters in our construction appropriately to achieve security on the 128-bit level, we
get accumulator and witness sizes that are promising — and perhaps can be further optimized to become
truly practical.

1.1   Technical Overview
In this subsection, we present an overview of our Module Short Integer Solution (M-SIS) based positive
replacement-free accumulator (PRFA), i.e. a positive dynamic accumulator in which deleted elements can-
not be re-added. Our accumulator can support polynomially many deletions for optimal parameters and
admits an efficient zero-knowledge commit-and-prove argument to prove membership of an element.

Homomorphic Operations. First, we recall a key equation from lattice-based cryptography that was first
laid out by Gentry, Sahai and Waters [GSW13] and Boneh et al. [BGG+ 14]. Let R ⊇ Z be a ring, Rq =
R/qR, with q ∈ Z, and F = {f : {0, 1}ℓ → {0, 1}} be a family of Boolean circuits. For any f ∈ F,
A = [A0 | · · · | Aℓ−1 ] ∈ Rqn×ℓm , x ∈ {0, 1}ℓ , there exist matrices Af ∈ Rqn×m and Hf,x such that

                                  (A − x⊤ ⊗ G) · Hf,x = Af − f (x) · G                                    (1.1)

where G ∈ Rqn×m is a gadget matrix [MP12]. The matrix Af can be efficiently computed from the matrix
A and the function f , and the matrix Hf,x can be efficiently computed from the matrix A, the function
f , and the vector x. Moreover, if F is a family of indicator functions, i.e., each f ∈ F is defined with
respect to x̃ ∈ {0, 1}ℓ such that fx̃ (x) = 1 if x = x̃, then ∥Hf,x ∥∞ = 1 when G is the base 2 gadget
matrix(cf. Corollary 2.2.1). In addition, given a vector u ∈ Rqn , we can compress Hf,x and Af into vectors
hf,x = Hf,x · G−1 (u) and af = Af · G−1 (u), respectively, such that (A − x⊤ ⊗ G) · hf,x = af − f (x) · u
where G−1 (u) ∈ Rqm is a vector such that G · G−1 (u) = u.

Commit-and-Prove Argument. We show how to efficiently prove knowledge of the revocation attribute
x and its membership witness sx using the recently developed succinct zero-knowledge frameworks from
lattices. In short, the task boils down to proving knowledge of x ∈ {0, 1}ℓ and a short vector sx that satisfy
the following relation:
                                          [A | B − x⊤ ⊗ G] · sx = c.                                     (1.2)
    We first describe how to prove this type of statement in zero-knowledge using the LNP framework [LNP22a].
Other than the prover’s last message z (which is linear in the witness length), this proof is succinct. To
achieve succinctness, we replace z with a proof of knowledge of z satisfying the verifier of the LNP proto-
col; this step uses the LaBRADOR proof system by Beullens and Seiler [BS23], which provides concretely

                                                      5
attractive proof sizes. Note that, due the LNP layer above, we do not need to apply the zero-knowledge
variant of the LaBRADOR protocol. Although this general strategy has already been described in [BS23],
we provide a more explicit description suited to the statement in Equation 1.2 (see Appendix D for more
details). Finally, in Section 5 we describe how to upgrade the existing lattice-based anonymous credentials
[BLNS23b], [JRS23], [LCL+ 23], [AGJ+ 24], that follow the “signatures with efficient protocols” paradigm
[CL02b], to support credential revocation using our developed commit-and-prove system.
    We provide a concrete example of appending the revocation mechanism on top of the anonymous cre-
dential system implemented in the LaZer library [LSS24]. For the revocation attribute of length ℓ = 32, we
obtain the accumulator value c of size 50KB, while a membership witness sx has size 14.7MB (see Table 2).
By applying the composition of LNP and LaBRADOR protocols, our commit-and-prove argument produces
proofs of size at most 125KB. Although not yet fully ready for practical deployment, we believe this is a
stepping stone towards concretely efficient post-quantum positive accumulators with free addition.

We recall the definition of a positive dynamic accumulator.
Definition 3.1 (Positive Dynamic Accumulator [KL24]). A positive dynamic accumulator for a domain M
is a tuple of ppt algorithms ΠPAcc = (Gen, Add, Delete, MemWitCreate, MemWitUp, MemVer) with the
following syntax:

    • Gen(1λ , aux) → (pp, sk, A0 , st): Given λ ∈ N in unary and some auxilliary information aux, the
      algorithm Gen outputs the public parameters pp, the secret key sk, an initial accumulator value A0 ,
      and an initital state st.
    • Add(pp, sk, stt , At , x) → (At+1 , wx,t+1 , upmsgt+1 , stt+1 ): Given pp and sk, a state stt , an accumu-
      lator’s value At , and a value x ∈ M, if x is present in the accumulator, the Add algorithm aborts and
      returns ⊥. Otherwise, the Add algorithm adds x to the accumulator and outputs a new accumulator’s
      value At+1 , a witness wx,t+1 certifying that x is in the accumulator, update information upmsgt+1
      that can be used to update the membership witnesses of other elements, and an updated state stt+1 .
    • Delete(pp, sk, stt , At , x, wx,t ) → (At+1 , upmsgt+1 , stt+1 ): Given pp and sk, an accumulator’s value
      At , a value x ∈ M and its membership witness wx,t , the Delete algorithm removes x from the
      accumulator and outputs a new accumulator’s value At+1 , update information upmsgt+1 , and an
      updated state stt+1 .
    • MemWitCreate(pp, sk, stt , At , x) → wx,t : Given pp and sk, a state stt , an accumulator value At ,
      and a value x ∈ M that was accumulated, the MemWitCreate algorithm outputs a membership
      witness for x at epoch t.
    • MemWitUp(pp, x, wx,t , upmsgt+1 ) → wx,t+1 : Given pp, an element x ∈ M with its witness wx,t ,
      and an update message upmsgt+1 , the MemWitUp algorithm outputs an updated membership witness
      wx,t+1 for x.
    • MemVer(pp, At , x, wx,t ) → 1/0: Given pp, an accumulator value At , an element x ∈ M and its
      membership witness wx,t , the deterministic MemVer algorithm outputs 1 if wxt is a witness for x’s
      membership in the set represented by At , or 0 otherwise.

    In addition, ΠPAcc should satisfy the following properties:
    • Compactness: For any λ ∈ N, t = poly(λ), and x ∈ M, |At | = poly(λ) and |wx,t | = poly(λ, |x|).
    • Correctness (Informal): For any λ ∈ N, t = poly(λ), accumulator value At with associated public
      paremeter pp, element x ∈ S ⊆ M with up-to-date membership witness wx,t , where S is the set of
      elements accumulated in At ,

                                 Pr [MemVer(pp, At , x, wx,t ) = 1] ≥ 1 − negl(λ)

      We refer the reader to the work of Kemmoe and Lysyanskaya [KL24] for a formal definition.
Definition 3.2 (Communication efficiency). We say that a positive dynamic accumulator ΠPAcc is commu-
nication efficient if the size of upmsg grows linearly with the number of deletions that have occurred since
the last time the accumulator was modified.

Increasing the number of deletions. A trivial way to increase the bound on the number of deletions in
Construction 4.1 is to make the parameters superpolynomial in λ. Alternatively, using a Merkle tree (or a
similar data structure), we can increase the bound on the number of deletions in our PRFA from γ to k · γ,
with k ∈ N, without degrading the quality of the parameters. In brief, instead of sampling one vector c
uniformly at random, the accumulator manager will sample k vectors [c1 , . . . , ck ] and then hash them into a
Merkle tree by putting ci in leaf position i in the tree. Now, the root of the Merkle tree is our new accumulator
value. Observe that the resulting accumulator is still communication efficient: we can add an element x to
the new accumulator without changing its value by just adding x to the sub-accumulator associated with
one of the leaf matrices ci . In addition, we can delete an element y from this new accumulator by removing
y from its corresponding leaf associated with the vector cj ; as a result, the leaf in position j will need
to be replaced with the vector c′j and the Merkle tree will need to be recomputed to reflect that; updating
the Merkle tree requires log k computation and communication. Although this transformation allows us
to increase the number of deletions we can perform, it also increases the size of a membership witness to
incorporate the authenticating path in the Merkle tree. It also complicates using the resulting accumulator
as part of the commit-and-proof paradigm.

4.2     Obtaining an Adaptively Secure Positive Dynamic Accumulator
Baldimsti et al. [BCD+ 17, Theorem 1] showed how any non-adaptively secure positive dynamic accumula-
tor ΠPAcc can be turned into an adaptively secure Π′PAcc by combining it with an adaptively secure digital
signature Σ. In brief, to add an element x, we sample an element rx uniformly at random from the domain
of ΠPAcc and generate its membership witness w̃rx with respect to ΠPAcc . Then, we bind x to rx by using Σ
to generate a signature σx on the pair (x, rx ). Finally, the membership witness for x with respect to Π′PAcc
is the triple wx = (rx , σx , w̃rx ). To delete x from Π′PAcc , we only need to remove rx from ΠPAcc . Clearly,
Π′PAcc is adaptively secure since forging a membership witness for an element x′ results in either breaking
the security of Σ or forging a membership witness with respect to ΠPAcc for a random element. In addition,
if ΠPAcc is communication efficient, then Π′PAcc is also communication efficient.
     In Construction 4.2, we show how Baldimsti et al.’s compiler can be used to transform any selectively
secure PRFA into an adaptively secure positive dynamic accumulator. For any element x, to ensure that the
replacement free condition of the underlying PRFA is not violated, we sample a fresh random element rx
everytime x is added to the accumulator.

5.1     Signatures with efficient protocols from lattices
