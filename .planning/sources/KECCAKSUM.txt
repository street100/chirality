<h1 class="page-title"><span class='sc'>Keccak</span> specifications summary</h1>
</div>
</header>
<div class="container">
<p><span class='sc'>Keccak</span> (pronounced [k&#603;t&#643;ak], like “ketchak”) is a family of sponge functions that has been standardized in the form of SHAKE128 and SHAKE256 extendable output functions and of SHA3-224 to SHA3-512 hash functions in <a href="specifications.html#FIPS_202">FIPS 202</a>, as well as cSHAKE128, cSHAKE256 and other functions in <a href="specifications.html#SP_800_185">NIST SP 800-185</a>. The text below is a quick description of <span class='sc'>Keccak</span> using pseudo-code. In no way should this introductory text be considered as a formal and reference description of <span class='sc'>Keccak</span>. Instead the goal here is to present <span class='sc'>Keccak</span> with emphasis on readability and clarity. For a more formal description, the reader is invited to read the <a href="files/Keccak-reference-3.0.pdf">reference specifications</a> or the <a href="specifications.html#FIPS_202">FIPS 202</a> standard.</p>
<p>As a complement, one can also have a look at some simple implementations focused on readability and clarity, such as:</p>
<ul>
<li>Markku-Juhani O. Saarinen's <a href="https://github.com/mjosaarinen/tiny_sha3">tiny_sha3</a>;</li>
<li>our own readable and compact implementation <a href="https://github.com/XKCP/XKCP/blob/master/Standalone/CompactFIPS202/C/Keccak-readable-and-compact.c">in C</a> or <a href="https://github.com/XKCP/XKCP/blob/master/Standalone/CompactFIPS202/Python/CompactFIPS202.py">in Python</a>.</li>
</ul>
<h1>Structure of <span class='sc'>Keccak</span></h1>
<p><span class='sc'>Keccak</span> is a family of hash functions that is based on the <a href="sponge_duplex.html">sponge construction</a>, and hence is a sponge function family. In <span class='sc'>Keccak</span>, the underlying function is a permutation chosen in a set of seven <span class='sc'>Keccak</span>-$f$ permutations, denoted <span class='sc'>Keccak</span>-$f[b]$, where $b \in \{25, 50, 100, 200, 400, 800, 1600\}$ is the width of the permutation. The width of the permutation is also the width of the state in the sponge construction.</p>
<p>The state is organized as an array of $5 \times 5$ lanes, each of length $w \in \{1, 2, 4, 8, 16, 32, 64\}$ and $b=25w$. When implemented on a 64-bit processor, a lane of <span class='sc'>Keccak</span>-$f[1600]$ can be represented as a 64-bit CPU word.</p>
<p>We obtain the <span class='sc'>Keccak</span>$[r,c]$ sponge function, with parameters capacity $c$ and bitrate $r$, if we apply the sponge construction to <span class='sc'>Keccak</span>-$f[r+c]$ and by applying a specific padding to the message input.</p>
<h1>Pseudo-code description of the permutations</h1>
<p>We first start with the description of <span class='sc'>Keccak</span>-$f$ in the pseudo-code below. The number of rounds $n$ depends on the permutation width, and is given by $n = 12+2l$, where $2^l = w$. This gives 24 rounds for <span class='sc'>Keccak</span>-$f[1600]$.</p>
<pre><code>Keccak-f[b](A) {
  for i in 0…n-1
    A = Round[b](A, RC[i])
  return A
}

Round[b](A,RC) {
  # θ step
  C[x] = A[x,0] xor A[x,1] xor A[x,2] xor A[x,3] xor A[x,4],   for x in 0…4
  D[x] = C[x-1] xor rot(C[x+1],1),                             for x in 0…4
  A[x,y] = A[x,y] xor D[x],                           for (x,y) in (0…4,0…4)

  # ρ and π steps
  B[y,2*x+3*y] = rot(A[x,y], r[x,y]),                 for (x,y) in (0…4,0…4)

  # χ step
  A[x,y] = B[x,y] xor ((not B[x+1,y]) and B[x+2,y]),  for (x,y) in (0…4,0…4)

  # ι step
  A[0,0] = A[0,0] xor RC

  return A
}
</code></pre>
<p>In the pseudo-code above, the following conventions are in use. All the operations on the indices are done modulo 5. <code>A</code> denotes the complete permutation state array, and <code>A[x,y]</code> denotes a particular lane in that state. <code>B[x,y]</code>, <code>C[x]</code>, <code>D[x]</code> are intermediate variables. The constants <code>r[x,y]</code> are the rotation offsets (see <a href="keccak_specs_summary.html#rotationOffsets">Table 2</a>), while <code>RC[i]</code> are the round constants (see <a href="keccak_specs_summary.html#roundConstants">Table 1</a>). <code>rot(W,r)</code> is the usual bitwise cyclic shift operation, moving bit at position <code>i</code> into position <code>i+r</code> (modulo the lane size).</p>
<h1>Pseudo-code description of the sponge functions</h1>
<p>Then, we present the pseudo-code for the <span class='sc'>Keccak</span>$[r,c]$ sponge function, with parameters capacity $c$ and bitrate $r$. We assume for simplicity that $r$ is a multiple of the lane size, as this is the case for the standard instances.</p>
<p>The description below assumes that the input <code>M</code> is represented as a string of bytes <code>Mbytes</code> followed by a number (possibly zero, at most 7) of trailing bits <code>Mbits</code>. The standard instances typically add a few trailing bits for domain separation. When made of bytes, the input of these functions then becomes <code>Mbytes</code>, while <code>Mbits</code> is solely determined by the instance used, see <a href="keccak_specs_summary.html#suffixes">Table 3</a>.</p>
<pre><code>Keccak[r,c](Mbytes || Mbits) {
  # Padding
  d = 2^|Mbits| + sum for i=0..|Mbits|-1 of 2^i*Mbits[i]
  P = Mbytes || d || 0x00 || … || 0x00
  P = P xor (0x00 || … || 0x00 || 0x80)

  # Initialization
  S[x,y] = 0,                               for (x,y) in (0…4,0…4)

  # Absorbing phase
  for each block Pi in P
    S[x,y] = S[x,y] xor Pi[x+5*y],          for (x,y) such that x+5*y &lt; r/w
    S = Keccak-f[r+c](S)

  # Squeezing phase
  Z = empty string
  while output is requested
    Z = Z || S[x,y],                        for (x,y) such that x+5*y &lt; r/w
    S = Keccak-f[r+c](S)

  return Z
}
</code></pre>
<p>In the pseudo-code above, <code>d</code> is the delimited suffix, which encodes the trailing bits <code>Mbits</code> and its length. The padded message <code>P</code> is organised as an array of blocks <code>Pi</code>, themselves organized as arrays of lanes. The variable <code>S</code> holds the state as an array of lanes. The <code>||</code> operator denotes the usual string concatenation. See also the page on <a href="keccak_bits_and_bytes.html">bit and byte conventions</a> for more details.</p>

<p>The value of the capacity <i>c</i> and of the suffix <code>Mbits</code> jointly provide <em>domain separation</em> between the different instances. Because their input to <span class='sc'>Keccak</span> never collide, domain-seprated instances will give unrelated outputs and act as independent functions.</p>
<p>The <em>customizable</em> extendable-output functions cSHAKE128 and cSHAKE256 from <a href="specifications.html#SP_800_185">SP 800-185</a> have their own domain separation mechanism. In addition to the main input, these functions accept a <em>function name</em> input (defined by NIST) and a <em>customization string</em> input (user-defined). When these two additional inputs are both the empty string, cSHAKE128 and cSHAKE256 fall back on their corresponding SHAKE functions. The functions KMAC128, KMACXOF128, TupleHash128, TupleHashXOF128, ParallelHash128, ParallelHashXOF128 are defined on top of cSHAKE128, and similarly for KMAC256, KMACXOF256, TupleHash256, TupleHashXOF256, ParallelHash256, ParallelHashXOF256.</p>
