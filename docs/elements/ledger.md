# chirality LEDGER — the category map over the E#/T# element sets

**What this is.** The single live index that maps every element to a **semantic
category** and a **module** (a scope-pull unit). Read *down a category* to see
everything of one kind; pull a *module* to scope a coherent chunk of work.

**Referencing (`CAT·E#`).** In prose, planning, and trackers, refer to an element by
its **category prefix + stable number** — `SYS·E121`, `MEM·E120`, `EF·E42`. The prefix
is *this ledger's category* (a readable "what it is"); the `E#` stays the **stable
global key**. Files (`examples/E121-*.md`), the pipeline tooling (`chirality-pack.py E121`),
and cross-references keep the **bare `E#`** — the prefix is a display label, not a
rename, so recategorizing an element changes only its prefix, never its identity.
Side-project element sets (`T#`, `S#`) are **already namespaced by their own letter**
— they take **no `CAT·` prefix**; the letter *is* their category axis.

**What this is NOT.** Not the detail. Element rows (title, external reference,
rationale) live in `SELF-IMPLEMENT-CATALOG.md`; per-element build-state authority
is `records/conformance-map.md`; concept refractions are `docs/banks/`.
This ledger only carries the *mapping* — category, module, coarse state, and
cross-citations. When state here and CONFORMANCE-MAP disagree, **CONFORMANCE-MAP
wins** (this column is a pointer, not a snapshot to maintain in parallel).

**Axes.**
- **Category** (primary): *what an element is*, not what kind of work it is. The
  old catalog §sections mixed lifecycle (SELF-HOST / REPLACE-CRUTCH / BUILD-PROPER)
  with area; here lifecycle is gone from the axis and area is the axis.
- **Module**: a named, bounded subset you pull and work as one unit — finer than a
  category, may cross-cut. This is the "smaller scope pulls."
- **State** (coarse): `built` · `flight` (in pipeline now) · `design` (unbuilt) ·
  `superseded` (the element stopped being the thing that gets built — its work was
  reshaped into a *different* element, named in the Title cell. The row STAYS: deleting
  it is how history is lost while the artifacts sit on disk. The matching pipeline
  status and the `superseded_by:` frontmatter field are defined in
  `docs/examples/INDEX.md`).
- **Cites**: cross-links to side-project ledgers (`TUI:T#`, `scriba`) — see §Z.
- **Track** (added 2026-08-31, the last column of every table below): which of the
  author's two tracks the row is on, per `docs/decisions/decision-scope.md`. `SH` = the current self-hosting track. `OT` = the
  deferred ownership-and-trust track, which is not to be pulled into current work and
  whose documents are not to be audited. `?` = UNSORTED, an author call.
  The sourcing rule and the UNSORTED list live in `SELF-IMPLEMENT-CATALOG.md`; this
  column mirrors it row for row and adds nothing of its own. `SH` is a track marker
  and asserts nothing about whether a row is required, scheduled, or started.
  Every row of category **TR** is `OT` except **E52**, which an audit has already put
  to the author (`.planning/handoffs/TEST-AUDIT-AND-SCOPE-RECATALOG.md`). The six
  reserved **CRY** slots are `?`: they are slots rather than elements, and the CRY note
  below founds `crypto-secret-independence` on E59 + E60, both `OT`.

**Side projects stay separate.** `TUI/CATALOG.md` (T#) and scriba are their own
ledgers. They are wired to core by **citation only**, both directions: a core
element a side-project consumes tags `→TUI`; a side-project's core-delta
(e.g. T1–T3 tty crossings) is cited *into* SYS. Never merged.
