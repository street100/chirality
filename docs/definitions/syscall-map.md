# Syscall coverage map (x86-64)

> GENERATED by `bin/syscall-map.py --md`. Do not hand-edit the table — it parses
> the kernel's own `unistd_64.h` (nr → name), classifies each call into a family,
> and joins against the three built layers: the tal crossings
> (`lib/sys-tal.chiral`), the typed face (`lib/ports.chiral`), and the host
> referents (`impl_ports.py`). Regenerating on the same host is byte-identical.

**Status legend.** `BUILT` = a native tal `nb-sys-*` crossing exists (chirality
issues the syscall itself). `FACED` = a typed face extern reaches it, but only
through the CPython referent today (the E51 transport-swap targets). `-` =
**UNMODELED**: no crossing, and denied at the chokepoint.

**How the surface is governed (`docs/decision-syscall-governance.md`).** The
model is default-deny at an enforced chokepoint, NOT enumeration of all 362
(that would be the longer-denylist antipattern P1 rejects). As of 2026-07-28
(E76) the type-level chokepoint is real: `tal.py SYSCALL_TABLE` is the
enumerated permitted set, `check_fn` refuses an unregistered `ti-sys` and binds
each crossing's name to its number. So every UNMODELED row is **denied by
absence at tal-check** — not an open hole, and not a call "we owe a wrapper."
BUILT+FACED is what chirality *performs* (hand-written, grows with need); the
UNMODELED count is correct-by-design.
